# v2.1.0

## 背景

v2.0.0 证实了 best-of-N 能把 lt/ppo_mask 的 success_rate 从 N=8 的 52.5%
推到 N=1024 的 95%——这说明已训练好的随机策略，对几乎每个测试场景，
"成功的行为"其实已经存在于它的采样分布里，只是 N=1（确定性/单次采样）
时不一定被选中。这个发现本身留了一个明显的后续问题：**best-of-N 只是把
推理阶段的算力（多次重试）换成了成功率，训练本身完全没变**——如果一次
部署真的只能试一次（重试有真实代价），这个方案就用不上。

于是很自然地问：能不能把"重试才能撞上的成功路径"，训练进策略本身，
让它在 N=1 时就更可能一次做对？

## 本版本改动：Self-Imitation / Expert Iteration 微调原型

新增 [scripts/self_imitation_finetune.py](../scripts/self_imitation_finetune.py)，
思路是 RL/LLM 文献里的标准套路（Expert Iteration / Self-Imitation Learning /
Rejection Sampling Fine-tuning，LLM 那边的 STaR 用的也是同一个机制），
本仓库此前只把它用在"ILP 专家轨迹"上（`shared/bc_pretrain.py` 的
BC warm-start），这次是**同一套 BC 监督学习机制，改喂策略自己生成的
成功轨迹**：

1. 对 `TRAIN_SCENARIOS`（160个）逐个用当前策略做最多 N=64 次随机采样
   （`deterministic=False`），保留第一条完全成功的轨迹（(obs, mask, action)
   序列）；一次都没成功的场景不贡献数据。
2. 把收集到的所有成功轨迹，用 `shared/bc_pretrain.py::pretrain_actor_critic`
   （原本用于 ILP 专家 BC 热启动的同一个函数）做监督微调——本质是让策略
   模仿自己的高光时刻。
3. 微调后在测试集上重新评估 N=1（确定性）和 N=8，看单次成功率是否真的
   往上抬。
4. 重复 3 轮（sample → BC微调 → 评估），观察是否持续改善或很快饱和。

冒烟测试（5个train/5个test场景，N=8，2 epoch）验证了链路本身没问题：
微调后 N=8 success_rate 从 0.80 → 1.00（样本太小，不能当结论，只验证
代码路径可用）。正式跑（160训练场景，N=64，10 epoch，3轮）已在后台启动，
复用 v1.2.4 seed=42 的模型（`0e1a36bb_bc/model_0e1a36bb_bc_v1.2.4`）。

### 已知局限

- 那 2 个"N=8192都放不下"的场景（[v2.0.0_scenario_detail.md](v2.0.0_scenario_detail.md)
  的 idx=26/32）没有任何成功轨迹可采，本方法对它们无能为力——self-imitation
  只能把"能成功但要靠运气"变成"更容易成功"，救不了真正一次都赢不了的场景。
- 是微调（fine-tune），不是从零重新训练——用的是已经收敛的 v1.2.4 模型
  继续调，不是推翻重来。
- 只在 `lt/ppo_mask` 上验证，`ppo_lagrangian`/其余算法未覆盖。
- BC 微调用的学习率、轮数、每轮采样 N 都是第一次尝试的初始值，没有调参。

## 实验结果（v1：纯BC微调，负面结果）

正式跑（160训练场景，N=64，10 epoch/轮，3轮）跑完了：

| | N=1 (deterministic) success_rate | N=8 success_rate |
|---|---|---|
| 基线（微调前） | 0.425 | 0.525 |
| round 1 后 | 0.350 | 0.500 |
| round 2 后 | 0.300 | 0.575 |
| round 3 后 | 0.300 | 0.625 |

**核心假设不成立，而且方向反了**：N=1 单次确定性成功率不但没有提升，
反而单调下降（42.5%→30%），N=8 倒是比基线略有提升（52.5%→62.5%），
但那只是"重试机制还在起作用"，跟"把成功轨迹训练进策略"这个目标无关。

判断原因：纯监督 BC loss（`-log_prob(自采样成功动作)`）会把策略的动作
分布往一小撮（155/160场景、每场景仅1条）成功轨迹上使劲拉——BC训练acc
从92.6%一路涨到97%+，说明策略在向这个窄集合过拟合，副作用是压缩了
策略的探索/随机性，反而伤害了对其他测试场景的泛化。这是self-imitation
类方法的已知坑：纯BC容易导致分布坍缩，标准做法（Expert Iteration文献）
从来不会只做BC——BC之后必须跟一段用真实reward继续的RL训练，让奖励
信号把BC造成的坍缩纠正回来。

## 实验结果（v2：BC轻微调 + RL恢复，进行中）

新增 [scripts/self_imitation_finetune_v2.py](../scripts/self_imitation_finetune_v2.py)，
在 v1 的基础上修正：
- BC 轮数从10降到3、学习率从3e-4降到1e-4（减轻单步坍缩幅度）。
- **每轮BC微调后追加 `model.learn(200_000步)` 的真实PPO训练**（沿用原
  reward/GAE，不用 `RA.P4Callback`——那个callback会往
  `results/<scenario>/ppo_mask/.progress.json` 写数据，这是live dashboard
  读取"当前训练进度"的同一个文件，会跟正式训练的显示互相干扰；改用一个
  只记录episode AR、不碰共享进度文件的本地callback
  `_SilentEpisodeTracker`）。
- 新增 `results.json` 落盘，写到独立的伪算法目录
  `results/<branch>/lt/ppo_mask_selfimit/<exp_id>/`（不是 `lt/ppo_mask/`），
  这样能在 dashboard 上作为独立一行显示，同时不会覆盖 `lt/ppo_mask` 的
  正式训练结果卡片。

冒烟测试（5 train/5 test场景，N=8，2 epoch，2000步RL恢复）验证链路可用，
`results.json` 正确写入且能被 `/api/history/lt/ppo_mask_selfimit` 读到。
正式跑（3轮，N=64，160训练场景，200k步RL恢复/轮）已在后台启动，结果待补。
