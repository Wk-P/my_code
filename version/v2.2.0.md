# v2.2.0

## 背景

v2.0.0/v2.1.0 这两轮实验（best-of-N扫描、self-imitation微调）全部聚焦在
success_rate（能不能把15个服务都合法放完）上，AR（放置质量）从头到尾
只是被动观察的指标，从没被真正当作优化目标。原因追到底在reward函数——
[env.py](../scenarios/lt/ppo_mask/env.py)（v1.1.0确立的纯终局稀疏奖励）：

```python
reward = float(self.M) if total_viol == 0 else -float(self.M)
```

**只要成功（零违反），不管AR是0.55还是0.95，reward都恒为+M。** PPO的
梯度里从来没有"在都能成功的前提下应该往更高AR走"这个信号——
success_rate能被best-of-N/self-imitation这类手段推高，是因为它们直接
优化的就是"success"这个二元目标；但AR长期卡在0.61~0.65（vs ILP最优
0.7213）不是因为学不会，是因为**reward函数本身从来没要求它学**。

self-imitation（v2.1.0）还放大了这个问题：采样时"找到第一条成功轨迹就
停"，不筛选AR，模仿的对象本身就是质量未知的。

## 本版本改动：AR 进 reward，违规继续硬约束

按用户明确的两条要求实现：
1. **AR是提升目标**——不能只是被动指标。
2. **两种约束（容量/冲突）继续零容忍**——不能因为追AR而破坏这一条。

`scenarios/lt/ppo_mask/env.py::step()` 终局reward改为：

```python
reward = float(self.M) * self.ar if total_viol == 0 else -float(self.M)
```

- 零违反时：reward与AR成正比（`M*AR`），让梯度真正区分"AR=0.55的成功"
  和"AR=0.90的成功"，而不是像之前一样给同样的+M。
- 有违反时：reward保持`-M`不变。由于AR∈(0,1]，`M*AR <= M`，而
  `-M < 0 < M*AR`对任意AR恒成立，**"任何成功都优于任何违规"这个优先级
  关系在数学上自动保持**，不需要额外调权重去平衡两个目标的量级。
- Action masking（硬约束）本身没有改动，容量/冲突违反率依然应该恒为0
  ——这条reward只影响"极少数因mask全False被迫fallback"的边界情况，
  不改变正常路径下"违规不可能发生"这个事实。

## 影响范围与验证方式

- 只改了 `lt/ppo_mask/env.py` 一个文件，`eq`/`gt`场景和其余算法
  （`ppo_lagrangian`/`ppo_opt`/`dqn`/`ddqn`）的reward未改动。
- **这是训练目标的根本性改动，不能靠微调验证，必须完整重跑5M步**——
  用标准 `scripts/resume_scenario.sh lt ppo_mask_bc` 流程（而不是side
  脚本）重新跑一遍 `run_all_bc.py`，这样能正确写入 `results.json`、
  被dashboard正常追踪进度，不会像self-imitation实验那样游离在标准
  pipeline之外。
- 已用 `TRAIN_SEED=42`（与之前所有lt/ppo_mask实验同一个train/test划分）
  启动，跑完后对比：
  - AR是否真的从0.61~0.65往ILP的0.7213方向靠近；
  - success_rate（N=1/N=8/best-of-N=1024）是否因为reward目标从纯
    二元变成"二元+质量"而受影响（理论上不应该下降，因为违规惩罚的
    优先级没变，但需要实测确认）。
