# v2.3.0

## 背景

针对"lt/ppo_mask success_rate 又一次很低"（v2.2.0 的 `e251a0fb_bc` 只有
47.5%）的排查，一开始怀疑是 state 设计信息不够（policy 学不出"这一步会
不会导致后面无路可走"），于是给 `env.py` 加了一维显式的瓶颈风险特征
（`bottleneck_risk`，见下）。但做隔离对照实验时意外发现，真正的大头
不是 state 设计，是 **BC 预训练**。

## 隔离实验结果（同一批 40 个标准 held-out 测试场景，best-of-8）

| 配置 | 步数 | BC预训练 | bottleneck特征 | success_rate | AR mean |
|---|---|---|---|---|---|
| 基线 `e251a0fb_bc`（v2.2.0原始） | 5,000,000 | 有 | 无 | 47.5% | 0.6325 |
| 去掉BC，步数不变 | 5,000,000 | 无 | 无 | **70.0%** | 0.6347 |
| 步数再减到500k | 500,000 | 无 | 无 | 80.0% | 0.6005 |
| 加bottleneck特征 | 500,000 | 无 | 有 | 85.0% | 0.6199 |

逐变量拆解：
- **去掉BC（同样5M步）**：success_rate 47.5%→70.0%（**+22.5pp，四个变量里贡献最大**），AR几乎不变（0.6325→0.6347）。说明BC暖启动（ILP专家轨迹行为克隆）在v2.2.0的"AR-proportional终局reward"设定下是净负面因素，不是预期中的"帮助更快收敛"。
- **步数5M→500k（都无BC）**：success_rate继续+10pp，但AR掉0.03——训练时间存在真实权衡（练得越久，少数高风险场景上越容易"闯"进死胡同，但闯成功时质量更高），不是单调"越训练越好"。
- **加bottleneck特征（500k基础上）**：success_rate+5pp，AR也小幅提升，双指标同向，但样本只有单次训练，未做多seed，不能视为定论。

## 决策：永久停用 BC 预训练

**结论已定，不需要进一步验证**——BC预训练对当前reward设定是净负面，`run_all_bc.py`
/ `scripts/self_imitation_finetune*.py` 这类依赖BC暖启动的流程今后不再作为
标准训练路径使用（历史结果和脚本保留，不删除，仅停止在新实验里采用）。
今后 lt/ppo_mask（以及待验证的其余场景/算法组合）一律用 `run_all.py`
（不含BC步骤）作为标准训练入口。

**尚未解决、需要后续验证的问题**：这个结论目前只在 `lt/ppo_mask`
一个（场景,算法）组合上验证过，`eq`/`gt` 场景和其余算法
（`ppo_lagrangian`/`ppo_opt`/`dqn`/`ddqn`）是否有同样的BC负面效应尚未测试。

## 新分支：`add_states`

state设计（bottleneck_risk特征）本身没有被证伪，只是贡献比预想的小，
仍然值得继续研究——已开新分支 `add_states`（基于本次去掉BC后的干净基线），
后续针对observation设计的实验都在这个分支上做，不污染主线。当前分支已有
的改动：`scenarios/lt/ppo_mask/env.py` 的 observation 从 `5N+6+2M` 维
扩到 `5N+7+2M` 维，新增 `bottleneck_risk`（剩余服务里valid_ecu_count<=1
的占比，聚合的"死胡同临近"信号）。

**后续动作**：
- 在无BC基线（5M步）上补跑一次带bottleneck特征的对照，确认+5pp这个增量
  在完整训练步数下是否还成立（目前只在500k步验证过）。
- 多seed重复，把当前单次训练的方差量化清楚。
- 验证BC停用结论是否对eq/gt场景、其余算法同样成立。
