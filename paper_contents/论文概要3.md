# 论文概要3:基于Safe RL逼近ILP最优解的在线服务部署研究

> 本文件在`论文概要2-[exp-data].md`基础上,补充两项个人评论中提出的内容:(1)训练过程图表(AR/reward等学习曲线)的现状盘点与补充计划;(2)reward与AR目标函数的正式公式说明。`论文概要2-[exp-data].md`本身不再改动,作为该阶段的实验数据快照保留。

## 研究动机

现有的服务部署/放置优化问题多依赖传统优化算法(如ILP)求解,但这类方法存在一个共同局限:**针对不同的环境,需要人工重新设计约束公式与目标函数**,缺乏跨环境的智能泛化能力【论文引述:待补】。

强化学习(RL)为此提供了一条可能的路径——不再依赖人工设计的公式,而是让模型通过与环境交互自主学会求解目标,从而具备跨环境的适应能力。但在真实部署场景下,直接使用传统RL存在明显问题:训练/探索过程中可能违反容量、冲突等安全约束,而这类违规在生产环境中往往是不可接受的。因此本文选择**Safe RL**路线,在保证不违反安全约束的前提下,让模型在环境中逼近ILP这一理论最优解,以模型学习替代人工公式设计。

## 研究基础与依据

- 问题建模(VM/服务放置模式)参考【论文1】。该论文提出了一组优化算法组合,解决了服务放置问题中的最优放置,并同时考虑了隐私冲突相关的安全性约束;其公式体系分为三组,设计与求解难度较大。本文以该问题设定为基础,针对同一目标设计Safe RL模型,尝试找到一条逼近ILP最优解、但不依赖人工公式设计的途径。
- Safe RL方法论参考【论文2】【论文3】(具体引用待正文阶段确定;此处先记录依据来源与思路)。

## 初步实验观察

在三种资源供需结构的场景下初步测试:

- 资源紧缺型、供需均衡型、资源充裕型场景整体反馈良好;
- 但在**资源紧缺型(服务数多于ECU数)**场景下,失败率明显偏高;
- 即便模型在不触碰安全边界的前提下完成了全部分配,其最终优化目标值(AR)相比ILP最优解仍偏低。

对此的初步归因是:Safe RL策略难以摆脱"贪心"倾向——每一步决策只能看到当前状态下的局部最优,无法预见当前分配对后续可行性/质量的影响。据此做了针对性调整,但结果是**成功率有所提升,优化目标(AR)本身并未随之提升**——这与后续正式实验中"成功率与分配质量此消彼长"的发现相互印证。

## 阶段性结论(个人研判,待正文验证与精炼)

1. Safe RL 相比不带安全机制的普通RL模型,整体表现更好。
2. 在特定环境下,Safe RL 的优化结果能够较大程度地逼近ILP最优解——但需预先说明:ILP是数学意义上的全局最优解,Safe RL本质上无法超越它,只能逼近。

### 四、实验设计说明:只保留被最终版本确认的结论

本项目实验历时多个版本迭代(v0.x~v2.8.0),其中部分早期版本的结论后来被证明是**测量误差或错误假设导致的伪结论**,已被后续版本修正或推翻,写论文时不应引用这些中间过程,只取"最终被确认成立"的版本链条。下表明确标出被淘汰的错误路径,避免论文中出现已作废的数字:

| 版本 | 结论 | 状态 |
|---|---|---|
| v0.3.1 | feasibility-shaping对lt场景success_rate是负结果 | 已回滚(v0.3.2),不采用 |
| v1.2.0 | 训练步数5M→2M表面收敛 | **已被v1.2.3证伪**:valid_placed曲线实际未收敛,lt恢复5M步 |
| v1.2.2 | best-of-N(N=8)评估下success_rate 42.5%→65.0% | **已被v2.0.0推翻**:N=8从未调过参,N从8→1024时success_rate能到95%,此前"lt存在≈65%系统性瓶颈"的结论作废 |
| v2.1.0 | Self-Imitation/Expert Iteration微调 | 负结果,6轮验证核心假设不成立,不采用 |
| v1.1.0 | "稀疏终局reward只对ppo_mask有效"→归因为动作掩码是必要条件 | **已被v2.8.0推翻**:真正分界线是reward是否分级,不是有无掩码(见4.3) |

最终采信的实验链条是:v2.0.0(best-of-N敏感性,修正评估方法)→ v2.2.0/v2.4.0(终局reward改为AR分级)→ v2.3.0(BC预训练停用)→ v2.8.0(场景池200→2000、steps消融、reward继续探索、分级reward推广到无掩码算法)。以下按此链条组织实验内容。

### 五、实验一:评估方法修正——best-of-N敏感性(v2.0.0)

早期(v1.2.2)引入best-of-N重采样评估(N=8)缓解在线不可回溯策略的成功率上限,lt/ppo_mask的success_rate由此从42.5%升到65.0%,当时据此认为lt场景存在≈65%的系统性瓶颈(v1.2.4用多seed 42/1/2/3/4验证,均值≈0.640,区间0.575~0.675,一度被当作"非seed方差的真实瓶颈")。

v2.0.0对N做了敏感性扫描(N=8→1024),发现success_rate随N持续上升,N=1024时可达95%——**N=8本身从未被调过参,此前的"65%系统性瓶颈"其实是评估参数选择不当造成的假瓶颈,而非策略能力的真实上限**。这一发现同时定位出40个场景中确有2个高利用率难例是真正卡死不可解的。此修正确立了后续实验统一的评估协议基础。

### 六、实验二:终局奖励从二元改为按AR分级(v2.2.0 / v2.4.0)

**改动**:终局reward由二元信号(`+M`/`-M`)改为——不违反约束时给`M*AR`(AR为本次分配质量)、违反约束时给`-M`,使梯度能区分"同样成功但分配质量不同"的策略,同时保持"任何成功优于任何违规"的硬约束优先级不变。

**改动前(v1.1.0,二元reward,AR为成功/失败混合统计口径)**:

| 场景 | ppo_mask AR(gap) | ppo_lagrangian AR(gap) |
|---|---|---|
| lt | 0.6362(0.0851) | 0.6658(0.0555) |
| eq | 0.5281(0.0040) | — |
| gt | 0.5750(0.0587) | — |

**改动后(v2.4.0,AR分级reward,add_states分支)**:eq场景AR gap 0.0698→**0.0036**,gt场景AR gap 0.1690→**0.0522**,均缩小至原来的1/5~1/30。v2.4.0同时发现eq/gt此前一直误用v1.1.0的旧二元reward(从未获得AR梯度信号),是这两个场景此前gap偏大的直接原因;修复后这是v2.4.0中单项影响最大的改动。

### 七、实验三:BC预训练的停用(v2.3.0)

隔离实验(lt场景,同一批40场景,固定5M步,仅有无BC预训练一个变量):

| 配置 | success_rate | AR mean |
|---|---|---|
| 保留BC预训练(基线) | 47.5% | 0.6325 |
| 去掉BC预训练 | **70.0%**(+22.5pp) | 0.6347(基本不变) |

BC预训练被判定为当时发现的最大单一负面因素,之后永久停用。**注意**:此结论目前仅在lt场景下被严格验证;记忆记录显示BC在eq/gt场景可能有相反效果(对AR gap反而不利),但本次未在现有版本文档或results数据中找到eq/gt的BC对照具体数字,论文中若要下"场景相关"的结论,需要补做eq/gt的同类隔离实验,不能直接引用lt的结论外推。

### 八、实验四:场景池扩容与steps消融(v2.8.0)

**8.1 场景池200→2000**

lt场景严格控制steps=2M时:

| 场景池规模 | success_rate |
|---|---|
| 200(单seed) | 45%~57% |
| 2000(5-seed均值) | **83.5%~84.4%** |

提升幅度超过此前任何一轮reward调整,是本项目实验过程中的方向性转折点。

**8.2 训练步数2M vs 5M(2000场景池,5-seed)**

| 场景 | steps | success_rate | AR mean |
|---|---|---|---|
| lt | 2M | 84.4%±1.5% | 0.6201±0.0040 |
| lt | 5M | 83.5%±1.6% | 0.6211±0.0029 |
| eq | 2M/5M | 100.0%±0% | 0.5404 / 0.5410 |
| gt | 2M/5M | 100.0%±0% | 0.5844 / 0.5857 |

差异均落在种子间标准差范围内,**steps从2M加到5M没有真实效果**,说明瓶颈不在训练是否充分,而在场景覆盖是否充分。

**8.3 reward继续调整:成功率与AR此消彼长(lt场景,2000场景池,5M步)**

| 配置 | success_rate | AR mean |
|---|---|---|
| 基线(无课程/无降权) | 83.5%±1.6% | 0.6211±0.0029 |
| v2.6.0(失败惩罚降权) | 79.75%±1.05% | **0.6492**±0.0030 |
| v2.7.1(AR权重课程学习) | 81.75%±1.32% | 0.6410±0.0026 |

两类改动都能提升AR,但都以success_rate下降为代价,v2.7.1的平衡略优于v2.6.0,但都未实现"success不掉、AR还涨"的双赢。

**8.4 反直觉发现:成功场景的AR反而低于失败场景(v2.7.1,5-seed,eval复用已训练模型)**

| 拆分 | AR mean±std |
|---|---|
| 全部400个测试场景(混合) | 0.6462±0.0022 |
| 只看成功场景(~325/400) | **0.6418±0.0024** |
| 只看失败场景(~75/400) | **0.6649±0.0032** |

机制推测:要保证全部服务放完且不违规,策略需把服务更分散地铺到更多ECU上留余量;失败的那些局往往是策略更激进地把服务集中放置(AR更高)但未留够余量,最终卡死。**"能成功"本身是靠牺牲AR换来的,不是自然而然的副产品。**

**8.5 把AR分级reward推广到无掩码的5种算法(lt场景,5M步,5-seed)——⚠ 2026-09-03重新分类**

原表格把这5个算法统一称为"无掩码算法",但逐个核对`env.py`源码后发现它们在"约束是否被机制性保障"这一维度上其实分属三个不同类别,笼统合并会高估"reward分级本身"这一因素的解释力,必须分开呈现:

| 类别 | 算法 | 约束机制说明 | success_rate(分级reward后) | AR mean |
|---|---|---|---|---|
| 真·无约束(完全靠reward自学) | ppo | 无任何机制,违规与否纯粹事后判定 | 34.65%±1.68% | 0.6767±0.0031 |
| 真·无约束 | dqn | 同上 | 33.15%±8.04% | 0.6515±0.0028 |
| 真·无约束 | ddqn | 同上 | 36.30%±4.06% | 0.6544±0.0049 |
| 软约束机制(非掩码,但有机制) | ppo_lagrangian | 拉格朗日对偶,reward里持续施加违规惩罚项,是一种约束保障机制,只是不像掩码那样硬性 | **80.50%±1.60%** | 0.6403±0.0017 |
| 启发式修复兜底(非RL学习) | ppo_opt | 策略选到违规动作时,环境用一个写死的best-fit启发式(挑req/cap密度最高的合法ECU)**静默替换**该动作,只扣-0.1轻惩罚提示;违规是否被避免主要取决于这个经典启发式能否找到修复方案,不是策略自己学会的 | 60.15%±4.94% | 0.6273±0.0074 |

**对结论的影响**:
- 真正能验证"reward分级让完全无约束的算法也能学出策略"这一论点的,只有ppo/dqn/ddqn这3个——它们从0跃升至33%~37%,证据仍然成立,但幅度比原来笼统写的"27%~80%"要保守得多。
- ppo_lagrangian的80.5%高成功率,本身就该归功于"分级reward + 它自带的Lagrangian软约束机制"两者叠加,不能算作"无约束也能学好"的证据,这一点v2.8.0.md原文其实已经用括号注明过("大概率是分级reward叠加了它本身自带的Lagrangian软约束机制"),之前整理进本文档时被简化丢失了,现在补回来。
- **ppo_opt不应该被算进"无掩码算法"这一组**:它的60.15%成功率主要是best-fit启发式兜底的结果,不是RL策略学会避让约束,把它和ppo/dqn/ddqn混在一起对比会造成"分级reward对无约束算法普遍有效"的证据被高估。论文正文如果要用这组实验支撑"reward分级是关键"这一论点,应该只引用ppo/dqn/ddqn三个,ppo_opt要么单独作为"启发式-RL混合基线"讨论,要么在方法一节里就说明它不是一个严格意义上的"策略自主避让约束"的对照组。

### 九、核心结论

1. **在线、单步、不可回溯的决策范式下,RL(含Safe RL)的AR与ILP最优解之间存在约0.10~0.12的稳定差距**(以lt场景为代表)。累计10+轮独立实验(不同reward机制、不同steps预算、不同算法family)全部收敛到success 27%~90%(与算法/场景结构相关)、AR 0.60~0.68这一区间,判断这是决策范式本身的结构性上限,而非奖励设计不充分。
2. **真正带来实质改善的是两类不同性质的杠杆**:数据侧的场景多样性(200→2000场景池)和信号侧的奖励分级(二元→按AR连续分级),而非在"分级reward"框架内部继续调整权重比例(v2.6.0/v2.7.1这类微调只能在success/AR之间此消彼长)。
3. **动作掩码不是学出有效策略的必要条件**,真正的必要条件是reward是否分级——这是本文对既有认知的一处修正,而非既有认知的延伸。⚠ 需要精确措辞:这一结论的证据来自ppo/dqn/ddqn这3个**完全不带任何约束机制**的算法(分级reward后成功率33%~37%),不包括ppo_lagrangian(它有拉格朗日软约束机制)和ppo_opt(它靠启发式修复兜底,不是策略自主学会避让),后两者的高成功率不能算作"无约束也能学好"的证据,详见8.5节的重新分类。
4. **边界声明**:ILP是数学意义上的全局最优解,RL(含Safe RL)本质上只能逼近、无法超越。

### 十、局限性与未来工作
- **缺乏独立验证集**:目前所有"是否保留某项reward改动"的判断都直接依据测试集结果,等同于把测试集当验证集用。若要作为论文"泛化能力"的正式依据,需要补充独立验证集。
- **多数改动仅在lt场景下验证**:eq/gt因成功率已饱和(接近或等于100%),未重复跟进v2.6.0~v2.8.0的全部对比实验,包括BC对eq/gt的效果目前缺乏具体数据支持,不能直接外推。
- **初步实验中"贪心局限"的归因目前仍为定性判断**(个人叙述部分提到的单步决策无法预见后续影响),v2.8.0的"成功场景AR更低"现象是对这一判断的间接支持,但尚未设计专门实验(如引入前瞻性价值估计/多步回报塑形)做定量验证。

### 十二、reward与AR目标函数的公式说明

个人评论指出:"我们还要对reward以及我们的目标AR进行公示说明,这些公式和引用也要说明。"以下是按当前代码(`scenarios/lt/ppo_mask/env.py`,v2.8.0/v2.7.1状态)整理的公式,论文正文需要在此基础上补充符号表与相关引用。**⚠ 此公式并非在三场景×六算法上都同构实现,实际核查结果见12.6节,写正文前必须先读12.6。**

> **⚠ 2026-09-03核实结果:下方12.3公式并非三场景统一实现,详见12.6。**

**12.1 问题符号**

- $N$:ECU(计算单元)数量,$M$:服务(待部署)数量。
- 第 $t$ 步(对应第 $t$ 个待部署服务)时,策略选择动作 $a_t \in \{1,\dots,N\}$,表示把当前服务放置到第 $a_t$ 个ECU上。
- 动作掩码方法中,$a_t$ 被限制在满足容量约束与冲突约束的可行ECU集合内;无掩码方法中,任意 $a_t$ 均可选,违规由环境判定并终止/惩罚。

**12.2 目标函数:资源利用率 AR(Allocation Ratio)**

$$
AR = \frac{\sum_{i=1}^{N} ru_i}{n_{active}}
$$

其中 $ru_i$ 是第 $i$ 个ECU上已放置服务的资源利用率(单个ECU内利用率之和,由具体容量占用计算得到),$n_{active}$ 是当前有至少一个服务被放置的ECU数量(空ECU不计入分母)。AR越接近1,说明活跃ECU的资源被利用得越充分。ILP以最大化最终AR为目标函数求解全局最优部署方案,是RL方法的比较基准。

**12.3 终局奖励(graded reward,v2.4.0起对全部6种算法统一采用同一公式族)**

非终止步:

$$
r_t = 0 ,\quad t < M
$$

终止步($t=M$)按是否违反约束分两支:

- **无违规**(容量与冲突约束全程满足):

$$
r_M = M \cdot \big[(1-w)\cdot 1 + w\cdot(2\cdot AR - 1)\big]
$$

其中 $w \in [0,1]$ 是AR权重课程系数(v2.7.1引入,`shared/adaptive_ppo.py::ar_weight_at()`),随训练步数从0退火升到1:训练初期($w\to0$)只奖励"完成放置"这一事实,训练中后期($w\to1$)才把奖励拉开到与AR质量强相关,退火节奏在v2.7.1中设定为训练进度50%时$w$升到1(v2.7.0设定为训练末尾才到1,被验证为无效配置)。$w=1$时上式退化为v2.4.0原始公式 $r_M = M\cdot(2\cdot AR-1)$。

- **发生违规**(容量或冲突约束被违反,至少一步):

$$
r_M = -M \cdot \Big(1 - \frac{valid\_placed}{M}\Big)
$$

其中 $valid\_placed$ 是违规发生前(含违规发生时刻周围)已合法完成放置的步数,取值范围令该分支的奖励落在 $(-M, 0]$,并保证 $r_M^{violation} < r_M^{success}$ 对任意 $AR>0$ 恒成立(即"任何成功优于任何违规"的硬约束优先级)。v2.6.0之前该分支为固定 $-M\cdot(1-\tfrac{valid\_placed}{M})$ 到 $-2M$ 的范围(失败惩罚强度是成功奖励量级的2倍),v2.6.0将其压缩到与成功奖励同量级 $(-M,0]$,实验显示AR均值上升但success_rate被侵蚀(见8.3表格),因此v2.8.0最终结论未把v2.6.0设为默认配置,仅作为受控对比的一组。

**12.4 势函数塑形项(potential-based reward shaping)**

除终局奖励外,每一步额外叠加一个势函数塑形项,不改变最优策略(Ng et al.风格的potential-based shaping,理论上保证策略不变性)【引用:待补——势函数塑形的理论依据出处】:

$$
F(s_t,a_t,s_{t+1}) = \gamma\,\Phi(s_{t+1}) - \Phi(s_t), \qquad \Phi(s) = -\beta\cdot\big(1 - \text{FFD\_feasibility}(s)\big)
$$

其中 $\text{FFD\_feasibility}(s)$ 是对状态 $s$ 下剩余待放置服务能否被首次适应递减(First-Fit-Decreasing)启发式全部合法放置的可行性估计(取值$[0,1]$,越接近1表示越可行),$\beta$ 是塑形强度系数,$\gamma$ 是折扣因子。v2.4.0第二次尝试将势函数从"逐服务、短视"的`_bottleneck_risk()`(经10-seed消融验证为零效应)换成`1-FFD_feasibility()`这一"联合、看剩余子问题整体"的风险估计。

**12.5 待补充引用**

- 【论文1】VM/服务放置问题建模来源(三组公式、隐私冲突约束)。
- 【论文2】【论文3】Safe RL方法论依据(动作掩码/拉格朗日对偶各自的理论出处)。
- Potential-based reward shaping的理论依据(Ng, Harada & Russell风格的策略不变性证明)出处。

**12.6 三场景×六算法reward公式实际同构性核查(2026-09-03,直接读取`scenarios/{lt,eq,gt}/{算法}/env.py`源码确认)**

12.3节的公式**只在lt场景的6种算法上完全成立**。实际逐文件比对结果如下,论文正文中"三场景统一采用同一套reward公式"这一表述必须改写,否则是事实错误:

| 算法 | lt(资源紧缺) | eq(供需均衡) | gt(资源充裕) |
|---|---|---|---|
| ppo_mask | 完整v2.7.1公式:$M\cdot[(1-w)+w(2AR-1)]$,含AR权重课程$w$与势函数塑形项 | 仅v2.4.0版本:$M\cdot(2AR-1)$,**无**课程$w$、**无**势函数塑形 | 同eq |
| ppo_lagrangian | $M\cdot(2AR-1)$(分级) | **`+M if 无违规 else -M`**(二元,未migration) | **`+M if 无违规 else -M`**(二元,未migration) |
| ppo | $M\cdot(2AR-1)$(分级) | **二元reward**(未migration) | **二元reward**(未migration) |
| dqn | $M\cdot(2AR-1)$(分级) | **二元reward**(未migration) | **二元reward**(未migration) |
| ddqn | $M\cdot(2AR-1)$(分级) | **二元reward**(未migration) | **二元reward**(未migration) |
| ppo_opt | $M\cdot(2AR-1)$(分级) | **二元reward**(未migration) | **二元reward**(未migration) |

即:v2.8.0第8.5节"把分级reward推广到5种无掩码算法,success_rate从0跃升至27%~80%"这一实验**只在lt场景做过**,eq/gt的这5种算法从未接受同样的改造,目前仍停留在v1.1.0时代的二元reward。eq/gt能达到接近100%的success_rate,是在**二元reward**下取得的(eq/gt本身供需宽松,不违规完成分配相对容易),不能被读成"分级reward在eq/gt上也验证过"。

1. 第九节核心结论第2条"真正带来实质改善的是……信号侧的奖励分级"这一论断的证据**目前只在lt场景成立**,写正文时必须加限定词,不能泛化到"三场景"。

### 十三、方法流程伪代码

补充个人评论第二点:除了reward/AR公式,还需要一版流程级伪代码,说明"场景生成→ILP基准→RL训练→评估→对比"这一整条实验管线是如何跑起来的,以及单个episode内部的决策/reward计算逻辑。以下伪代码基于`scenarios/*/ilp`、`scenarios/*/{算法}/env.py`、`shared/adaptive_ppo.py`、`shared/ilp_utils.py`的实际实现整理,不是抽象示意。

**13.1 整体实验管线**

```
输入: 场景类型 scenario ∈ {lt, eq, gt}, 算法列表 ALGOS, 随机种子集合 SEEDS

# 1. 场景池生成(每个scenario独立)
scenarios_pool ← generate_config(scenario, n_total=2000)   # v2.8.0:200→2000
对每个场景校验ILP可行性,不可行的场景丢弃,直到集齐n_total个可行场景
划分 TRAIN_SCENARIOS, TEST_SCENARIOS ← split(scenarios_pool)  # 目前无独立VAL,见局限性

# 2. ILP基准(每个场景独立求解一次,结果按 content_hash(场景内容) 缓存)
for s in TEST_SCENARIOS:
    ILP_AR[s] ← solve_ILP(s)          # 全局最优,数学上界
ILP_baseline ← mean(ILP_AR[s] for s in TEST_SCENARIOS)

# 3. 逐算法训练与评估
for algo in ALGOS:
    for seed in SEEDS:
        env ← make_env(scenario, algo, seed)       # 见13.2 单episode逻辑
        policy ← train(env, algo, total_steps=SCENARIO_TOTAL_STEPS[scenario])
        results[algo][seed] ← evaluate(policy, TEST_SCENARIOS, best_of_N=N)  # 见13.3

# 4. 汇总与对比(不跨场景平均,逐场景单独呈现)
for algo in ALGOS:
    success_rate[algo] ← mean over seeds of results[algo][seed].success_rate
    AR_mean[algo]       ← mean over seeds of results[algo][seed].AR (仅success episode)
    AR_gap[algo]        ← ILP_baseline - AR_mean[algo]
输出: {算法 → (success_rate, AR_mean, AR_gap)} 表,即9节核心结论的数据来源
```

**13.2 单个episode内部逻辑(以ppo_mask/lt的完整版本为例,对应12.3~12.4公式)**

```
初始化: valid_placed ← 0, total_ru ← 0, n_active ← 0, violations ← 0
for t = 1 .. M:                                    # M个服务依次到达,一次一个,不可回溯
    svc ← services[t]
    if 动作空间使用掩码(ppo_mask/ppo_lagrangian):
        candidate_ecus ← {i : 放svc到ECU_i 满足容量约束 AND 冲突约束}
        if candidate_ecus为空:
            action ← 剩余容量最大的ECU(fallback,记为违规)
        else:
            action ← policy.sample(candidate_ecus)  # 掩码严格限制采样空间
    else:                                           # ppo/dqn/ddqn/ppo_opt:无掩码
        action ← policy.sample(all_ecus)             # 违规与否交给环境事后判定

    ru ← 放置svc到ECU_action产生的资源利用量
    是否违规 ← 容量超限 OR 冲突集合冲突
    if 违规:
        violations += 1
    else:
        valid_placed += 1
        total_ru += ru
        if ECU_action此前为空: n_active += 1

    AR_t ← total_ru / max(n_active, 1)              # 12.2式,逐步累积

    # 势函数塑形(仅lt/ppo_mask v2.4.0第二版实现,见12.4式)
    Phi_s      ← -beta * (1 - FFD_feasibility(当前剩余子问题))
    Phi_s_next ← -beta * (1 - FFD_feasibility(转移后剩余子问题))
    shaping    ← gamma * Phi_s_next - Phi_s

    if t < M:
        reward_t ← 0 + shaping
    else:                                           # 终止步,按12.3式计算
        if violations == 0:
            w ← ar_weight_at(当前训练进度)            # 12.3式的课程系数,仅lt/ppo_mask启用
            reward_t ← M * ((1-w)*1.0 + w*(2*AR_t - 1.0))
        else:
            reward_t ← -M * (1 - valid_placed / M)
        reward_t += shaping

    policy.observe(state_t, action, reward_t, state_{t+1})
返回: episode是否成功(violations==0), 最终AR_t(仅成功时纳入AR_mean统计)
```

**13.3 评估阶段:best-of-N重采样(v2.0.0确立的评估协议)**

```
for s in TEST_SCENARIOS:
    trials ← []
    for k = 1 .. N:                     # N的取值本身是v2.0.0敏感性扫描的对象,而非固定超参
        trials.append(run_episode(policy, s, seed=k))
    best ← argmax_{trial in trials, trial.success} (trial.AR)  # 优先取成功episode,按AR择优
    if best存在: 记为success, AR=best.AR
    else: 记为failure
```
